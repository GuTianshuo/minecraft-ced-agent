# 0001 环境与算力边界

日期：2026-11-14 / 15
状态：已采纳

## 背景

原设计文档以 Fabric + Carpet + 正式版 Minecraft 为主线，硬件写的是 RTX 4080，
模型规模写 0.8B–1.5B；实施规划 v2 已改为 5M–30M 起步。两者冲突，必须先定死。

## 决策

1. **原生 Ubuntu，不用 WSL2。** 图形与进程通信性能不做假设，观战客户端也在 Ubuntu 跑。
2. **暂不接触正式版 Minecraft 本体。** 主训练环境改为 Craftium（Luanti 分支，Gymnasium 接口），
   Fabric 迁移后置到 P4。
3. **本轮参数上限 30M。** 不做任何 ≥0.5B 的方案。
4. **对照实验一律 3 个种子**，种子间成功率标准差 > 10 个百分点视为结果不可用。

## 理由

- 决策 2 把 Java 改动 Minecraft 内部结构的风险移出了关键路径：Lua 扩展 API 的稳定性远高于
  混淆后的 Minecraft 内部结构，首轮出结果从约 90 天压到约 6 周。
- 决策 3 是账本推论不是态度：16 GB 卡上 0.5B 只能 QLoRA 级微调，与"自建 CED 主干"直接冲突。
  30M 全量训练约 0.5 GB 权重梯度 + 2–3 GB 激活，留得下余量。

## 代价（必须记住）

- Luanti ≠ Minecraft：方块物理、移动速度、碰撞盒、交互时序都不同。
  在 L1 上得到的结论只对**架构假设**成立，不能宣称"能玩 Minecraft"。
- 迁移到 L3 时策略需要重训；可复用的是 schema、训练栈、评测口径、模型代码。
- 30M 规模上 CED 的收益主要来自"读多写少的成本不对称"，这个收益在更大模型上才显著；
  本轮的结论应当写成"在这个规模下是否可观测"，而不是"CED 是否更好"。

## 影响

- `docs/design.md` 中 0.8B–1.5B、RTX 4080、3.5 ms/tick、50 MB/小时 四处数值作废。
- 观测走结构化射线路线（路线 A），像素路线不作为本轮输入。
