# 0010 每个环节对模型意味着什么，以及和人的差别

日期：2026-11-16
状态：基于 data_room / data_room2 的实测统计与代码事实；不依赖某一轮训练结果

这份文件的用途：在继续加任务、加模型之前，把"模型实际拿到的东西"逐环节写清楚。
很多看起来像"模型不够聪明"的现象，根源在观测、采样或任务定义上，不在网络容量。

## 1. 观测：模型看到的不是画面

模型每一帧拿到 2568 个浮点数，分五段：

| 段 | 维度 | 实际内容（房间环境实测） |
| --- | --- | --- |
| rays | 256×9 | 16×16 条射线，每格 9 个特征 |
| self | 48 | 18 个自身状态 + 30 个恒零占位 |
| ents | 16×12 | **全 0**（还没实现实体感知） |
| audio | 4×3 | **全 0** |
| task | 12 | task_id、相对目标 dx/dz、距离、进度 |

### 射线不等于视觉

- 每格只有 9 个数：方块类、命中面法向 (3)、距离、高度差、水平距离、光照、形状。
- **没有颜色、纹理、材质、轮廓**。两个方块只要类别相同，在模型眼里就完全一样。
- 方块类只有 13 个显式命名类，其余按名字哈希到 14..200 的桶里。房间环境里实际只出现 3 个类（0=天空、29=珊瑚目标块、169=墙/地），
  也就是说这个任务里"视觉"的信息量接近二值。
- 16:9 视野（水平 70°、垂直 43.6°）下，命中分布按行：

```
行 0–4   全未命中（天空）      行 5 92% 未命中
行 6    28% 未命中             行 7–15 全部命中
```

  天空占 32% 的射线，下半 8 行是地面/墙，最底行平均命中距离 4.6 格。
- 单帧 18.7 KB 文本、58 帧/秒。这是"数据量像视频、信息量像点云"的组合。

### self 段：大部分维度在训练数据里是死的

用 data_room 全部 12578 帧统计，self 段有方差的只有 4 维：px、pz、yaw_sin、yaw_cos。
pitch 恒为 0（教师不低头），速度、着地、血量、饥饿、手持槽、光照在旧数据里是硬编码假值。
现在这些字段已经是真值（速度实测 2.4 格/秒、着地、血量、光照），但**对"走到点"这个任务，
策略只需要位置和朝向**，其余维度目前只是把真实状态放在那里，没有被任务逼着去用。

### task 段：这是给模型的"特权提示"

task 段直接给出目标相对坐标 (dx, dz)，精确到 1/32 格。真人玩 Minecraft 时看不到这个数字，
只能看到远处一个方块的样子和方位。模型拿到的是**已经在世界坐标里算好的向量**，
它要学的不是"看见目标"，而是"跟随一个已知向量转向并前进"。

这解释了为什么这个任务训练出来的策略看起来很"聪明"，却完全不依赖射线：
信息早就以最直接的形式喂进去了。消融（清零 task 段）应该会让成功率归零，
清零射线则几乎不掉——这正在测。

## 2. 动作：模型能做什么，不能做什么

14 个 token：10 个 0/1 键（前后左右、跳、潜行、aux1、挖、放、丢）、
9 类快捷栏、**121 档 yaw**（每决策 ±90°，分辨率 1.5°）、
121 档 pitch、4 档 hold。

| 项 | 实测/事实 | 和真人的差别 |
| --- | --- | --- |
| 决策频率 | 58 Hz（每个观测帧一个决策） | 人做显式决策约 2–10 Hz；58 Hz 更像"肌肉反射"被当成了决策 |
| 转向 | 每决策最多 ±90°，1.5° 一档，绝对角度由 Python 累计 | 人的转向是连续模拟量；这里是一串离散台阶 |
| 俯仰 | ±89.4° 夹紧 | 人抬头低头连续；这里的教师根本不用（pitch 恒 0） |
| 动作保持 | **只活一帧**，一次决策内部重复发约 3 帧 | 人按住键就是持续；这里必须显式重发 |
| 前进速度 | 4 节点/秒（pmul=1，接近人的步行 4.3） | 加速度 60 节点/秒²，起步/刹车比人硬得多 |
| 跳跃 | 单帧触发，约 40 帧升 0.89 格 | 人跳 1.25 格，且能边走边跳 |
| 冲刺 | 无（aux1 不加速） | 人 5.6 节点/秒 |
| 合成/背包 | **没有**，只有快捷栏切换 | 这是"经典玩法"里最大的一块缺失 |
| 挖/放 | 有，但需要对准；挖一格约 200 帧 | 人同样的方块约 10–20 帧（若按 58 Hz 折算） |

当前教师只用了 3 个维度：fwd、sneak、yaw。**其他 11 个 action 维度在数据里几乎全 0**
（pitch、hold、攻击、使用、丢弃、快捷栏都没有样本）。这意味着动作空间的大部分
从未被探索过，现在谈"模型学会了操作"为时过早——它只学会了"转向 + 前进"。

## 3. 奖励与任务：模型在优化什么

- 每 tick 奖励 = 距离减少量；到达 0.8 格内 +10 并终止。这是**密集整形**。
- 人玩这个游戏的目标通常是稀疏的（找到目标、打开门、拿到木头），中间没有"靠近一点 +0.02"的提示。
- 密集奖励让模型可以只学"沿着梯度下坡"，不需要理解"目标"这个概念；
  换成稀疏奖励或需要交互的任务（门、拉杆），这套信号会立刻不够用。
- 终止条件由 Lua 服务端计算，`truncated` 由 Python 在 300–400 决策时截断。

## 4. 记忆：16 帧 ≈ 0.28 秒

训练窗口 16 帧，在 58 Hz 下只有 **0.28 秒**的历史。人做同样的导航用秒级记忆，
做"拉杆—门开—穿门"这种状态化任务需要记住几秒前发生的事。
当前窗口对导航够用，对任何有状态的任务（门是否开着、方块是否挖开、物品是否捡到）都不够。

## 5. 评测：数字代表什么

- 种子决定世界布局和目标位置（同一个种子完全确定，已验证）。
- 贪心策略 + 确定性世界 → 每条种子只有一次 rollout；8 个 test 种子给出 8 个样本。
- 0001 要求"种子间标准差 ≤ 0.10 才算可用"。之前汇报的 67% 和 50% 都只有 2–3 个种子，
  标准差 0.43–0.48，按这个标准属于**不可用**；它们只能说明"管线通"，不能说明"学会了"。
- 人不是这样被评测的：人会换策略、会试错、会在不同随机世界之间泛化。这里的数字
  只对"这 8 个确定性世界"成立。

## 6. 与真人的差别，一张表

| 维度 | 模型 | 人 |
| --- | --- | --- |
| 视觉 | 256 条射线的类别/几何，无纹理 | 高分辨率彩色视觉，纹理和材质是主要线索 |
| 视野 | 70°×43.6° | 约 200° 有效视野，中心高分辨 |
| 深度 | 射线直接给距离 | 立体视觉 + 先验 |
| 听觉 | 全 0 | 有 |
| 实体感知 | 全 0 | 有 |
| 动作 | 14 维离散、58 Hz、逐帧重发 | 连续模拟 + 按住键 |
| 合成/背包 | 无 | 有，且是主要玩法 |
| 目标来源 | 精确坐标向量 | 视觉线索 + 语言 + 记忆 |
| 记忆 | 0.28 秒 | 秒到分钟 |
| 身体 | 步行速度接近人，加速度约 3–6 倍，无冲刺 | 有冲刺、有摔落伤害 |
| 死亡/饥饿 | 房间关闭伤害，无饥饿 | 有 |
| 学习方式 | 行为克隆一个脚本教师 | 试错 + 教学 + 语言 |

## 7. 对当前结论的影响

1. **房间任务测不出感知**。目标向量直接写在观测里，射线清零后策略大概率照常到达。
   在消融结果出来之前，任何"射线路线有效/无效"的说法都不成立。
2. **三档模型（GRU / Transformer / CED）在这个任务上的比较，测的是"跟随向量"的能力**，
   不是"看世界"的能力。CED 的设计动机（读多写少、编码器复用）在需要视觉的任务上才体现。
3. 要做真正像人的任务，必须先让**目标从观测里消失**（不给 dx/dz），
   只给"看见门/拉杆/树"的射线信号。这正是 T1 拉杆开铁门要验证的。
4. 密集奖励 + 精确目标向量会让"学会了"这个判断过于乐观。下一轮应当记录
   "去掉 task 段后的成功率"，把它作为感知能力的下界。
