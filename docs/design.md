# Minecraft CED Agent 设计文档

本文档描述一个以因果编解码器（CED, Causal Encoder-Decoder）为主干的 Minecraft 控制智能体的设计方案。项目处于设计阶段，下述内容为实现前的架构决策与参数约定。

---

## 1. 目标与约束

### 1.1 目标

给定 Minecraft 的游戏状态序列，输出键鼠动作序列，使智能体能够完成采集、建造、战斗、探索与长程目标（如速通）等任务。

### 1.2 硬约束

| 约束 | 数值 | 成因 |
| --- | --- | --- |
| 控制频率 | 20 Hz（50 ms / tick） | 与 Minecraft 逻辑帧率对齐 |
| 单帧动作延迟 | 1–2 ms（极简流） | 慢思考解码器无法进入高频回路 |
| 单卡显存 | 16 GB（RTX 4080） | 训练与推理同一张卡 |
| 参数规模 | 0.8B–1.5B | 由显存账本反推 |
| 感知公平性 | 不得透视、不得夜视 | 避免模型学到玩家不可能获得的信息 |

### 1.3 关键判断

高频控制回路里，模型 99% 的时间不需要说话。整个设计围绕这一点展开：把「读」（持续感知环境）与「写」（逐帧输出动作）拆开，让读的部分承担长上下文与记忆，让写的部分只保证足够快。

## 2. 架构选型

### 2.1 纯解码器（Decoder-Only）的局限

纯解码器对每个 token 都施加相同的层数与激活参数量。读入 10 万字日志与写出 100 字代码，计算模式完全相同。这带来两个问题：

- 持续感知场景下，输入远长于输出，算力被大量消耗在「读」上
- 追加输入必须全量重算，无法增量复用前缀缓存之外的历史

### 2.2 CED 的五项独有能力

以 CED 架构（前段为因果编码器、后段为解码器，如 DeepSeek-V4.1-Flash 的 20 + 20 层布局）为例，解耦预填充（Prefill）与自回归解码（Decode）后，具备纯解码器无法直接等价替代的能力。

**① 读写非对称分配**

预填充阶段直接跳过整个解码器：输入 token 只跑完编码器的 20 层（每 token 激活约 8B 参数），由编码器末层隐状态经线性投影生成解码器所需的全局 KV cache。只有生成输出时才流经全部 40 层（激活 16B 参数）。

衍生能力：动态深度跳层、超大规模输入的持续感知——低成本阅读、高成本决策。

**② 一对多同源异构解码**

编码器成为通用的「上下文内存编译器」。同一份编码器顶层表征可同时喂给多个解码器：2 层极小解码器做意图路由与安全拦截、20 层重型解码器做深度推理、扩散解码器生成图像音频。也支持多智能体并行解码，无需重复阅读输入。

**③ 隐空间压缩与记忆快照**

所有上下文信息汇聚在编码器顶层输出 $H_{\text{enc}}$ 上，按需投影给各解码器层：

$$K_l^{\text{dec}}, V_l^{\text{dec}} = W_l \cdot H_{\text{enc}}$$

$H_{\text{enc}}$ 是编码器末层输出，$W_l$ 是第 $l$ 层解码器专属的投影矩阵。不必为每个解码器层单独保存 KV cache，只存 $H_{\text{enc}}$（或降维后的版本），使用时乘 $W_l$ 即可还原，持久化体积可压缩至原来的 1/8 以下。

由此还可做隐空间检索增强：把代码库或文档预先编码为紧凑隐状态存成静态「记忆包」，推理时直接投影注入解码器。

**④ 局部双向与增量缓存兼得**

纯解码器使用严格单向因果掩码，前置文本存在视角盲区。传统编码器-解码器使用全双向注意力，追加一句就要全量重算。

CED 可以分块：编码器内部以「完整文档」或「单次工具返回结果」为单位开启块内双向注意力，块与块之间保持单向因果。单块有全局视野，历史前缀缓存又能 100% 命中。

**⑤ 解码器端多步并行**

输入上下文冻结在编码器侧提供只读信息，解码器侧序列短且与输入解耦，因此支持原生多 token 并行投机（验证过程无需重新穿透编码器）与迭代式全局编辑。

### 2.3 什么时候不需要 CED

如果任务始终是「读状态 → 想一两句 → 吐 1–3 个动作 token」，那么纯解码器加多输出头（Medusa 式并行头），或第 16 层分叉的浅深双出口混合 CED（Early-Exit Hybrid CED）就够了，没必要破坏预训练残差分布。

CED 真正有价值的场景是以下三条同时成立时：

1. **闭嘴干活的高频反射控制**：20 Hz 下多数帧只需输出操作，跳过慢思考解码器
2. **极长历史状态的显存压缩**：多帧状态累积数千 token，CED 只需缓存编码器状态
3. **时空混合注意力掩码**：同帧内部开启帧内双向注意力，跨帧保持因果单向

Minecraft 恰好三条全中。

## 3. 词表演进

### 3.1 第一版：32K 中英文 + 256 动作词表

开源模型（如 Qwen2.5 的 15.2 万词表）在 Embedding 与 LM Head 上消耗了 35%–45% 的总参数。第一版方案是裁剪到 32,768：

| 区间 | 用途 |
| --- | --- |
| `0–255` | 字节级回退与系统控制符 |
| `256–32511` | 高纯度中英文词表 |
| `32512–32767` | 256 个正交可组合动作词元 |

动作词元的分配：

- **电脑操纵**：32 动作原语 + 32 修饰键 + 128 UI 元素索引槽 + 64 归一化网格槽
- **肢体操纵**：128 VQ-VAE 技能码本 + 64 姿态表情 + 32 速度阻尼 + 32 目标锚点

### 3.2 第二版：砍掉自然语言词表

若把 Minecraft 的状态与 UI 全部外化为符号，动作空间也完全枚举化，模型内部就不再需要任何自然语言词表：

- **外部命令**：256 条固定命令，取 1–2 个正交组合，共 $16 \times 240 = 3{,}840$ 种无歧义指令
- **极简流 1**：128 维按键与离散动作
- **极简流 2**：基于 $\mu$-law 非线性量化的 $11 \times 11 = 121$ 档视角偏转 $(\Delta \text{Yaw}, \Delta \text{Pitch})$，加 7 个滚轮与归中指令

于是总词表从 32,768 降至 **2,048**。好处是省掉大模型外科手术（词表裁剪会破坏预训练分布），可以直接用 PyTorch 在 4080 上从零初始化训练一个纯粹的 0.8B–1.2B 状态-动作模型。

同等显存下，2K 词表的 1B 模型优于 32K 词表的 2B 模型：省下的约 6 GB 显存可用于拉长帧历史窗口，避免「金鱼脑」。

## 4. 显存预算与训练路线

### 4.1 显存账本

硬件为单张 RTX 4080（16 GB），训练栈为 BF16 + 梯度检查点 + FlashAttention-2 + 8-bit AdamW（`bitsandbytes`）。

- 每 1B 参数的权重、梯度与 8-bit 优化器状态约占 **6–8 GB** 显存
- 极简流**不能**沿用主文字流的 15 万词表，必须使用受限小词表（32–256 个控制/状态/动作 token）
- 主文字流若词表较大，需用 Liger-Kernel 的 `FusedLinearCrossEntropy` 避免实例化庞大的 logits 张量

### 4.2 两条路线

| | 路线 A：微调开源小模型 | 路线 B：从零预训练 |
| --- | --- | --- |
| 参数规模 | 0.5B–1.5B（如 Qwen2.5-0.5B/1.5B） | 0.2B–0.5B |
| 上下文长度 | 2,048–4,096 | 1,024–2,048 |
| 预估峰值显存 | 9–13 GB | 7–11 GB |
| 耗时预估 | 10 万条样本约 2–6 小时 | 5B tokens 约 2–4 天 |

路线 A 起步快、语言先验可用；路线 B 与 2K 纯符号词表方案更匹配，显存余量可全部用于上下文长度。

### 4.3 多流拓扑与联合损失

**拓扑模式**

- **模式 A（全局并行极简流）**：直接挂载在 $H_{\text{enc}}$ 上，用 1–2 层极薄 Transformer 或交叉注意力，在 2 ms 内输出意图/情绪/动作序列，主流同步吐字
- **模式 B（逐 token 伴随极简流）**：与主流同步步进，或从主流隐状态 $H_{\text{main}}$ 旁路分叉

**联合损失**

$$\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{main}} + \lambda_1 \mathcal{L}_{\text{min1}} + \lambda_2 \mathcal{L}_{\text{min2}}$$

$\mathcal{L}_{\text{main}}$ 为主文字流预测误差，$\mathcal{L}_{\text{min1}}, \mathcal{L}_{\text{min2}}$ 为两个极简流误差。$\lambda_1, \lambda_2$ 取 $0.1$–$0.3$，防止词表小、任务简单的极简流梯度在训练初期压倒主流。

### 4.4 动作精度预估

基于 0.5B–1.5B 底座与 64–256 个离散动作 token，契合 System 1 + System 2 与 VLA（Vision-Language-Action）范式。以下数据为设计阶段推演，尚未实测：

| 评估维度 | 肢体操纵 | 电脑操纵 |
| --- | --- | --- |
| 极简流首字延迟 | 2–5 ms | 3–8 ms（含高分辨率截图编码则 30–80 ms） |
| 生成频率 | 50–150 Hz | 30–80 actions/s |
| 高层语义动作准确率 | 88%–95% | 85%–93% |
| 底层连续/坐标控制准确率 | 40%–65% | 30%–55% |

底层控制的预估准确率低，原因是直接回归关节扭矩或让 1B 模型盲猜 1920×1080 下的绝对像素坐标都不现实。对应的补救方案：

- **肢体操纵**：极简流输出运动基元（Motion Primitives）或 VQ-VAE 动作码本 ID，交由底层强化学习小脑策略执行
- **电脑操纵**：用可访问性树（Accessibility Tree / UI Automation）或 Set-of-Mark 提取带编号控件，极简流输出 `[Action: LeftClick] [Target: #12]`，准确率可升至 90% 以上

两项通用增强：

1. **有限状态机语法约束解码**：推理时把非法后续 token 的权重置为 $-\infty$，零训练成本把格式合法率提到 100%
2. **主副流隐状态单向桥接**：极简流做交叉注意力时同时看到 $H_{\text{enc}}$ 与主流最新隐状态 $H_{\text{main\_last}}$，缓解「脑手不一致」，复合任务准确率可提升 10%–15%

## 5. 感知接口：去超能力化

游戏内方块相似度高（石头、安山岩、蠹虫石、暗处矿石难以分辨），而直接读取方块 ID 等于透视。设计上禁止赋予 AI 透视（X-Ray）与夜视，所有感知必须受玩家可达的物理条件限制。

### 5.1 两条感知路线

- **路线 A：结构化方块与实体感知**——直接读取方块与实体数据，但施加严格的可见性约束
- **路线 B：双分辨率 RGBD 视觉**——广角 $128^2$ 加准星中央凹原生裁剪 $64^2$，附去光照深度通道

结论是路线 A 胜出，理由见 5.7。

### 5.2 光照衰减与近似方块模糊映射

设目标方块表面光照度 $L \in [0, 15]$（取方块光照与天空光照最大值）、视线欧氏距离 $d$，定义有效清晰度：

$$V = \frac{L}{15} \cdot \exp(-\alpha \cdot d)$$

按 $V$ 四级降级：

| 条件 | 返回内容 |
| --- | --- |
| $L = 0$ 且 $d > 2$ | `<BLK_PITCH_DARK>`，等价于看不见，迫使 AI 下矿必须自带光源 |
| $0 < V < 0.25$ | `<FUZZY_DARK_SOLID>` 或 `<FUZZY_MOVING_SHADOW>` |
| $0.25 \le V < 0.65$ | 外观聚类簇 ID，如 `<CLUSTER_GRAY_ROCK>`（合并石头、圆石、安山岩、砾石、蠹虫石、凝灰岩、弱光煤矿）、`<CLUSTER_SANDY>`、`<CLUSTER_FOLIAGE>`、`<CLUSTER_DEEPSLATE_ORE>` |
| $V \ge 0.65$ | 真实 ID，如 `<BLK_IRON_ORE>` |

### 5.3 射线重建三维形状

发射 $16 \times 16$（或 $32 \times 16$）条射线。为避免低头看平地时因距离渐变误判为斜坡，结合俯仰角 $\theta_{\text{pitch}}$、偏航角 $\phi_{\text{yaw}}$ 与射线偏角 $(\delta_u, \delta_v)$，直接计算命中点相对玩家眼睛的重力对齐局部坐标：

$$\Delta y_{\text{height}} = d \cdot \sin(\theta_{\text{pitch}} + \delta_v), \quad d_{\text{horizontal}} = d \cdot \cos(\theta_{\text{pitch}} + \delta_v)$$

每条射线拼接 24 维特征：

| 特征 | 维度 | 含义 |
| --- | --- | --- |
| `Fuzzy_Block_Embed` | 12 | 模糊化方块嵌入 |
| `Block_Shape_Type` | 4 | 完整方块 / 半砖 / 楼梯朝向 / 流体 / 十字植物 |
| `Hit_Normal` | 3 | 命中顶面、底面或侧面 |
| `Spatial_Coord` | 5 | 归一化距离、相对高度 Δy、水平距离、光照 L/15、可破坏标志 |

经步长为 2 的 $3 \times 3$ 保形深度可分离卷积（含残差）压缩为 $4 \times 4 = 16$（或 32）个视觉几何 token，保留方块类型、台阶高度与墙壁形状。

### 5.4 身边感知只取暴露表层壳

**泛洪表层壳提取**：从玩家身体所在空气格出发，仅沿空气与透明方块做最大 5 格的 BFS，只采集直接接触连通空气的第一层固体方块表面（墙皮、地板、天花板）。墙体背面哪怕 1 格深就有铁矿、箱子或矿洞，一律返回 `<BLK_OCCLUDED>`，彻底杜绝穿墙透视。

**黑暗缩圈**：身边感知半径受自身光照度调制：

$$R_{\text{sense}} = 1.5 + 4.5 \times \left(\frac{L_{\text{self}}}{15}\right) \text{ 格}$$

全黑环境下缩至 1.5 格，等同于贴身触觉。

### 5.5 远距雷达只查视线终点落点

禁止扫描未见区块的底层调色板。只统计 $16 \times 16$ 射线中**最终被固体阻挡停下**（terminal hit，而非高空飞过）的区块，且命中射线数须满足与区块距离 $d_{\text{chunk}}$、目标光照 $L_{\text{target}}$ 挂钩的平方反比阈值：

$$N_{\text{hits}} \ge \tau(d_{\text{chunk}}) = \max\left(1, \left\lceil \frac{K_0}{d_{\text{chunk}}^2} \cdot \frac{L_{\text{target}}}{15} \right\rceil\right)$$

### 5.6 动态实体过滤

- **视锥裁剪**：只检测视野正前方 $\pm 70^\circ$、距离 $\le 32$ 格的实体
- **AABB 射线遮挡测试**：向实体包围盒的头、胸、脚发射 3 条射线，全部被不透明方块阻挡则判为穿墙不可见
- **光照模糊与听觉兜底**：可见实体同样受 $V = \frac{L}{15}\exp(-\alpha d)$ 制约，弱光远处只返回 `<ENTITY_MOVING_SHADOW>`；视野盲区或墙后 8 格内发出声音的实体，只在听觉雷达槽返回 `[声音类别, 粗略八方向, 音量档位]`，不暴露精确坐标

### 5.7 视觉路线的性能评估

传统 `glReadPixels` CPU 拷贝单帧需 15.5–25.5 ms，瓶颈在跨进程传输。改用 Fabric OpenGL FBO + CUDA-OpenGL Interop 显存零拷贝，配合 `torch.compile` 后：

| 环节 | 耗时 |
| --- | --- |
| 游戏离屏渲染 | 0.8 ms |
| 显存直通 | 0.2 ms |
| 双视野 CNN 编码 | 0.9 ms |
| CED 主干 | 1.6 ms |
| **合计** | **3.5 ms / tick** |

但若解冻 CNN 端到端微调，Batch=2、64 帧相当于同时保存 128 张双分辨率图的卷积激活，额外占用 6.5–9.0 GB 显存；且 RGBD 视频流每小时 8–15 GB，而路线 A 的二进制数据每小时仅约 50 MB。

因此**去超能力化后的路线 A 在训练速度（快 5–10 倍）、跨材质与光影泛化（对资源包与光影免疫）和几何精度上全面优于路线 B**。

## 6. 记忆系统

### 6.1 问题

仅靠滑窗上下文，即使 16K token、每帧 64 token，也只能记住 256 帧（12.8 秒）。出门砍树超过 13 秒就会忘记家在哪、箱子里放了什么。

### 6.2 单帧输入结构

单帧输入从 20 扩展到 **64 tokens/tick**，槽位划分如下：

| 槽位 | 内容 |
| --- | --- |
| `1–20` | 全局概览 |
| `21–44` | 身体状态与自身姿态、潜行等 |
| `45–56` | 局部感知与临时敌人威胁 |
| `57–58` | 主人位置与实时运动方向 |
| `59–64` | 三处据点指南针：主基地、矿洞据点、农田/工程工地 |

第 `57–64` 槽专门承担「家在哪」这类不可遗忘的空间锚点。

### 6.3 三级混合记忆

总计约 2,888–3,072 context tokens。

**第一级：最近全分辨率滑窗**
保留最近 16 帧（0.8 秒）完整 64 tokens/帧，共 1,024 tokens。用于战斗拼刀、盾牌格挡、跑酷起跳。

**第二级：帧池化情景记忆**
滑出 16 帧窗口后，用帧末的 `<FRAME_SUMMARY>` 词元把整帧浓缩为 2 个 KV 向量，每 4 帧（0.2 秒）采样一次。过去 3 分钟（3,600 帧）仅占 $900 \times 2 = 1{,}800$ tokens。

**第三级：永久空间地标寄存器 + 神经记忆银行**
地标寄存器即单帧 `57–64` 槽。记忆银行 $M_t$ 为 64 个常驻置顶 token：

$$M_{t} = \text{Gate} \cdot M_{t-1} + (1 - \text{Gate}) \cdot \text{CrossAttn}\left(M_{t-1}, H_{\text{enc}}^{(t)}\right)$$

$M_t$ 是模型常驻的 64 个记忆向量，$H_{\text{enc}}^{(t)}$ 是当前帧编码状态。每秒由门控判断当前看到的箱子物品或地形是否重要，重要则写入常驻区前端，永不遗忘。

## 7. 双模式与双速解码器

### 7.1 玩家随从（Follower NPC）

依托 `57–58` 槽（主人相对位置与实时速度朝向矢量）实现伴随预判走位：主人疾跑时侧后方同步跟随，主人潜行搭路时自动切入潜行后撤防挤落；也支持异地分派（去矿洞据点挖矿、农田收菜），主人遇袭时触发 `<STATE_MASTER_HURT>` 驰援。

五项插件特权（Paper / Citizens2 / Fabric）：

1. 工具无限耐久，或自动扣矿石瞬间修复
2. 随从专属 $3 \times 3$ 区块强加载（Chunk Ticket）
3. 3.5 格磁吸拾取；据点 4 格内 `<ACT_DEPOSIT_ALL>` 一键分类存箱
4. 配方书一键原子合成
5. 软性防卡死：连续 8 秒无位移注入 `<STATE_STUCK_WARN>`，15 秒未脱困则消耗饥饿度瞬移至安全路径点

### 7.2 独立 AI 玩家（Autonomous AI Player）

双层架构：上层「目的链条驱动器」每 2 秒更新 `Slot 01–04` 指令，下层为 20 Hz 的 CED 控制器。

三条目的链条：

- **硬核速通**：石器食物 → 铁装水桶 → 浇筑地狱门 → 猎杀烈焰人 / 猪灵交易 → 末影之眼定位要塞（写入 `Home 3`）→ 屠龙
- **田园生活**：基于马斯洛需求与昼夜节律的 Utility AI。残血撤退进食，黄昏回 `Home 1` 睡觉熔炼整理箱子，白天去 `Home 3` 收割 `AGE=7` 成熟作物并补种，或去 `Home 2` 鱼骨挖矿
- **蓝图建筑**：导入 `.litematic` / `.schem` 蓝图，与真实体素做差分，注入 `<GHOST_BLOCK_ID>` 幽灵方块与 `<WRONG_BLOCK_FLAG>`，自底向上逐层三维填色施工

### 7.3 双速异构解码器

**高频动作解码器（20 Hz，每帧必跑）**
2 层轻量交叉注意力加两个 128 维输出头（按键流 + 视角流）。

**低频状态与思考展示解码器（0.2–0.5 Hz）**
每 2–5 秒或被受击、卡死、切任务等事件唤醒，从 `1408–1535` 专属遥测词表中一次输出固定的 6-token 思考微包：

`[Mood 心境, Intent 当前主意图, Target 核心对象, Diag 受阻诊断, NextPlan 下步计划, Progress 进度预估]`

前端插件零延迟模板化渲染为随从头顶双行悬浮字（`TextDisplay` 全息气泡）与 AI 玩家右侧计分板（Scoreboard），并可回写至下一周期的输入指令槽，实现自我引导。

## 附录 A：MoE 专家尺寸背景

主模型设计里涉及 MoE 层的专家配置，此处记录相关结论。

**同构还是异构**
传统范式（Switch Transformer、Mixtral 8x7B）同层专家尺寸完全相同，原因是硬件效率：张量形状一致才能用 Grouped GEMM 批处理。现代范式（DeepSeekMoE、Qwen-MoE）引入共享专家与路由专家，尺寸可以不同。前沿范式则允许层间乃至同层内部专家尺寸异构，甚至包含参数量近零的特殊组件。

**异构为何有效**
token 难度分布极不均匀。高频虚词只需极小容量，强制分配大专家就是过度配置；罕见术语与多步推理则需要更大容量，尺寸被平均化就会欠拟合。按需分配算力可在更少激活参数下取得更低损失。

**代表做法**

- **HMoE**（arXiv:2408.10681）：同层内按等差数列（如相对尺寸 $\{9,11,13,15,17,19,21,23\}$）或同构异构混合配置专家，并加参数惩罚损失防止路由器总选大专家：
  $$\mathcal{L}_{\text{P}} = \mathbb{E}\left[\sum_{i=1}^{N} p_i \cdot \text{size}_i\right]$$
  $p_i$ 是 token 分配给第 $i$ 个专家的概率，$\text{size}_i$ 是其相对尺寸；激活的专家越大惩罚越高，简单 token 自然走小专家。
- **MoE++**（arXiv:2410.07348）：混入零计算专家（Zero Expert 丢弃输入、Copy Expert 残差直通、Constant Expert 替换为可训练常量），专家层前向吞吐提升 1.1–2.1 倍。
- **NAS 路线**（Structure Aware NAS for MoE 等）：把专家内部架构参数化，按数据子分布复杂度自动搜索宽度深度；压缩近 40% 体积下取得最高约 2 倍推理加速。
- **裁剪路线**（Fisher-MoE、CRISP）：用 Fisher 信息衡量参数敏感度，物理删除低重要性行列，把不同专家压成不同执行宽度；裁剪 50% 参数仍保持 99% 以上性能。
- **工程等效方案**（DeepSeekMoE、Dynamic Routing in MoE）：全部切成等尺寸微专家，改用 Top-P 动态路由代替固定 Top-K，简单 token 激活 1 个、困难 token 激活多个，既动态决定有效容量又保留同构矩阵的吞吐优势。
