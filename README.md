# Minecraft CED Agent

用因果编解码器（CED）驱动的 Minecraft 状态-动作模型。

> **项目状态：设计阶段，尚无实现代码。**
> 本仓库记录架构假设与实施规划，不是已完成系统的说明。初始设计的性能与架构结论尚需验证；最新落地路线见 [V2 本机训练与可视化实施规划](docs/implementation-v2.md)。

## 目标

当前落地硬件为 **i5-12600K / 48GB 内存 / RTX 4070 Ti SUPER 16GB**。以 Minecraft Java 1.20.1 + Fabric + Carpet 的无渲染服务端为主环境，先实现小模型状态-动作闭环，再验证 CED 与长程记忆；不预设必须从 1B 模型起步。部署与容量均待实测。

训练使用逻辑 tick 驱动，可测试加速步进；另外保留 **一个 20 TPS 实时演示服 + 图形观战客户端**，观看最新策略，不要求所有训练环境都渲染。演示不是训练 worker 的实时镜像，必须显示策略版本。双系统启动 Ubuntu 时，观战也在 Ubuntu 运行。

## 当前实施路线

- **环境**：原生 Ubuntu 优先，Java 17；Carpet 1.4.112，其他依赖在可运行构建后锁定。
- **训练接口**：自写 Fabric mod，提供观察过滤、动作、批量锁步、奖励与重置；尚未实现。
- **多开**：按 1 → 4 → 8 个训练环境压测，12–16 只作为可选测试档位，不是承载承诺。
- **模型**：脚本基线 → 小策略行为克隆/强化学习 → CED 对照 → 有证据后扩容。
- **观战**：独立实时演示默认开启，必要时将单个训练 worker 降速用于直接诊断。
- **公平性**：视觉、触觉、听觉与历史记忆分开，严格玩家模式和助手特权模式分开。

完整硬件预算、观战设计、环境协议、测试与验收标准见 [V2 规划](docs/implementation-v2.md)。

约束条件：

- **实时性**：99% 的 tick 不需要输出文字，控制回路必须在毫秒级完成
- **显存**：单卡 16 GB，权重、梯度、优化器状态与激活值全部要装下
- **公平性**：感知接口不得包含透视、夜视等玩家无法获得的信息
